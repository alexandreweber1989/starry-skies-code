| Prática | Significado | Versículo-chave |
|---------|-------------|-----------------|
| **Dízimo** (10%) | Reconhece soberania de Deus | Ml 3:10 — "fazei prova de mim" |
| **Ofertas** | Gratidão alegre, além da obrigação | 2Co 9:7 — "Deus ama a quem dá com alegria" |
| **Primícias** | Melhor parte, primeira confiança | Pv 3:9-10 — celeiros cheios |

## 🎯 Cultura Pastoral (Não Corporativa)

| Princípio | Como Vive |
|-----------|-----------|
| **Acolher, não controlar** | Painel do líder = "com quem conversei esta semana" — **não** frequência |
| **Dúvidas são bem-vindas** | "Venha como é" — não pressupõe jornada avançada |
| **Família real** | Mesas em casas — "onde a vida acontece de fato" |
| **Cada um sacerdote** | Não há "clero/leigos" — todos servem, todos discipulam |
| **Paternidade > Programa** | Relacional, não eventístico |

## 📋 Processo de Integração (Jornada do Novo Membro)

A apostila é um **curso progressivo** com:
1. **Lições** (história, pilares, mesa, ministério quíntuplo)
2. **Aplicações práticas** (perguntas de reflexão ao final de cada lição)
3. **Progressão** → Batismo → Cursos (Integração, Encontro, Discipulado I/II, Escola de Líderes, etc.)
4. **Meta**: "Novo Membro" → "Batismo" → "Cursos" → "Liderança" (jornada visual)

## 🔑 Princípios de Decisão para Produto/UX/Conteúdo

### Em **cada** decisão, aplicar o filtro:

> **Pergunta-filtro**: *"Isso ajuda a forjar discípulos através do relacionamento, da mesa e da paternidade?"*

### Linguagem Obrigatória
- **Termos da casa**: Mesa, Rede, Apascentador, Sacerdócio, Paternidade, Ministério Quíntuplo
- **NÃO usar**: jargão corporativo ("usuário", "engajamento", "conversão", "funil", "métricas de vaidade")
- **Tom**: Pastoral, acolhedor, "venha como é" — nunca "você precisa fazer X"

### Estrutura de Navegação (Respeitar Hierarquia)
```
Igreja
  └── Redes (Sabaoth, Zadoque, Jovens, Adolescentes)
        └── Mesas (células em casas)
              └── Membros
Ministérios (transversais): Louvor, Mídia, Dança, Kids, Atos de Amor
```

### Jornada do Usuário (Toda Feature Deve Servir)
```
Visitante → Integrando (cadastro lead) → Membro (batismo/cursos) → Líder (discipulado/escola) → Apascentador/Pastor
```

## 🛡️ Segurança & Arquitetura (Regras Técnicas)

### RLS (Row Level Security)
- ~80 tabelas com RLS ativo
- **NUNCA** usar `EXISTS` correlacionado em policies → **SEMPRE** funções `SECURITY DEFINER`:
  - `has_role`, `has_mesa_role`, `has_ministry_role`
  - `is_pastoral`, `is_leadership`, `is_mesa_member`, `is_rede_member`
  - `can_view_mesa`, `can_view_rede`, `shares_group`
  - `is_kids_admin`, `is_guardian_of`, `is_livraria_admin`, `is_cantina_admin`

### Enums Reais (NUNCA inventar valores)
```sql
app_role: admin_geral | admin_ministerio | lider_mesa | membro | admin_livraria | admin_cantina | admin_kids
church_function: pastor | apascentador | lider | diacono | obreiro | membro | lider_rede | lider_mesa | lider_ministerio
```

### Server Functions Pattern (Obrigatório)
```typescript
// src/lib/*.functions.ts → bundle CLIENTE
export const minhaFuncao = createServerFn({ method: "POST" })
  .middleware([requireSupabaseAuth])
  .validator((input) => schema.parse(input))
  .handler(async ({ data, context }) => {
    const { data: isAdmin } = await context.supabase.rpc("has_role", {
      _user_id: context.userId, _role: "admin_geral"
    });
    if (!isAdmin) throw new Error("Sem permissão");
    const { minhaLogica } = await import("./minha-logica.server"); // SÓ AQUI carrega server
    return minhaLogica(data);
  });

// src/lib/*.server.ts → código PURO servidor (supabaseAdmin, bypass RLS)
```

### Error Handling (Crítico)
```typescript
// ❌ ERRADO - try/catch NÃO pega erro RLS
try { await supabase.from(...).insert(...) } catch (e) {}

// ✅ CORRETO - supabase-js retorna {data, error}
const { error } = await supabase.from(...).insert(...);
if (error) throw new Error(error.message); // SEMPRE inclua error.message
```

## 📝 Diretrizes para Landing Page (index.tsx)

### O que JÁ funciona (manter)
- Identidade visual: "Uma casa sobre a rocha" (gancho poderoso)
- História real (Gênese) — 3 capítulos contam origem humilde → propósito
- CadastroLead — fluxo prático: perfil → bairro → mesa → WhatsApp do líder
- Ministérios visíveis — 9 áreas mostram amplitude
- CTA final acolhedor — "Você leu até aqui... procura um lar"

### O que FALTA (gaps para visitante de primeira viagem)
| Pergunta do Visitante | Status | Solução (Novo Componente) |
|----------------------|--------|---------------------------|
| "O que esta igreja acredita?" | Parcial (5 pilares teológicos = jargão) | Traduzir para linguagem de vida |
| "Como isso muda minha segunda-feira?" | ❌ Não respondido | **LifePromise.tsx** — promessa prática |
| "Eu me encaixo aqui?" | Parcial (pressupõe vontade) | **PastoralFAQ.tsx** — dúvidas reais |
| "Quando/onde vocês se encontram?" | Escondido no cadastro | **PracticalInfo.tsx** — visível sem cadastro |
| "Quem são os pastores/líderes?" | ❌ Não aparece | **WelcomeTeam.tsx** — rostos reais |
| "Como é um culto?" | ❌ Zero foto/vídeo | **SundayExperience.tsx** — 3 cards |
| "E se eu não for crente / estiver ferido?" | ❌ Não endereçado | **PastoralFAQ.tsx** + **/conheca** |

### Componentes Novos Propostos (Issues #1-7)
1. `LifePromise.tsx` — Hero: "Um lugar onde você pertence, cresce e faz diferença — mesmo nas segundas difíceis"
2. `SundayExperience.tsx` — Chegada/Culto/Depois (fotos reais ou ilustrações)
3. `PastoralFAQ.tsx` — Acordeão: batismo, dúvidas, filhos, solteiros, feridos, como conhecer alguém
4. `WelcomeTeam.tsx` — Pr. Geraldo + líderes de Rede/Mesa (paternidade visível)
5. `PracticalInfo.tsx` — Local, horários, WhatsApp, estacionamento, acessibilidade
6. `Testimonials.tsx` — 3 vídeos/cards: "Cheguei sozinho...", "Filhos amam Kids...", "Mesa virou família..."
7. `src/routes/conheca.tsx` — Página baixa pressão: FAQ + fotos + "venha sem compromisso"
